## 1. 무엇을, 왜 만드나

서울을 여행하는 사람이 **휴대폰으로** 대화하듯 물어보면, 근처 맛집과 관광명소를 추천하고 **귀여운 일러스트 지도에 핀으로** 보여주는 챗봇이다.

기존 소스(Spring JSP + FastAPI RAG)를 참고하되 새로 만든다. 기존 버전과 다른 점:
- 화면은 JSP가 아니라 HTML/CSS/JavaScript 정적 페이지 **[결정]**
- 백엔드는 FastAPI 하나로 통합 (Spring 제거, 대화 기록 저장도 FastAPI가 담당) **[결정]**
- 답변에 장소 목록이 함께 나오고, 지도에 핀으로 표시되며, 핀을 누르면 상세 정보가 뜬다 **[결정]**
- "근처"를 이해한다: 질문 속 장소 / 직전 대화의 장소 / GPS 현재 위치 **[결정]**

## 2. 목표 · 비목표 · 안티목표

### 목표
1. 멀티턴 대화: "거기서 카페도 있어?"처럼 앞 대화의 장소를 이어받는다. **[결정]**
2. 근처 맛집·관광지 추천 (한 번에 3~5곳 **[제안]**), 답변 텍스트 + 장소 목록 동시 제공.
3. 추천 장소를 일러스트 지도 위 핀으로 표시. 핀을 누르면 이름·분류·주소·전화번호·도보 시간(+대표 사진 **[제안]**) 카드 표시. **[결정]**
4. GPS 위치 기반 추천 (입력창의 📍 버튼). **[결정]**
5. 전화번호는 관광공사 API로 보강해서 보여준다. **[결정]**

### 3.1 첫 화면 — S2a "원형 배지 링" (`first-screen-s2a.html`)

- 둘레: 점선 원 위에 랜드마크 배지 6개 — 경복궁(근정전), DDP, 롯데월드타워, 63빌딩, 숭례문, 남산(N서울타워). 배지는 흰 원 + 파스텔 내부 원 + 점선 테두리.

- 아래: 인사말 "안녕하세요! 👋 / 서울 어디로 떠나볼까요?", 빠른 질문 칩(📍 내 주변 맛집 · 🏯 종로 관광지 · ☕ 성수 카페 등), 입력창(오른쪽에 📍 GPS 버튼).
- 랜드마크 일러스트는 시안의 SVG 함수(`palace`, `gate`, `namsan`, `ddp`, `b63`, `lotte`)를 그대로 옮겨 쓰면 된다.

### 3.2 추천 결과 화면 — 지도 펼침 (`result-screen.html`)
위에서부터:
1. 상단 바: "🗺️ 서울 여행 친구" + 오른쪽 "▾ 지도 접기"
2. **일러스트 지도** (둥근 모서리, 흰 테두리, 핑크 그림자)
   - 크림색 바탕(`#fdf6e3`), 초록 숲 덩어리(원·타원), 하늘색 강, 점선이 있는 흰 길, 파스텔 블록 몇 개.
   - 핀: 물방울 모양 + 이모지 + 흰 이름표. **맛집 = 주황(`#ff9f43`), 관광지 = 분홍(`#ff8fa3`)**. 선택된 핀은 1.25배.
   - 내 위치: 파란 점(GPS 사용 시).
   - 근처에 6대 랜드마크가 있으면 그 미니 일러스트를 지도에 함께 그림.
   - 범례: "🧡 맛집 · 🩷 관광지 · 🔵 내 위치".
3. **정보 카드** (핀을 누르면 지도 바로 아래에 열림, ✕로 닫기): 사진(없으면 이모지 타일) · 이름 · 분류 태그 · 📍 주소 · 📞 전화번호(없으면 "전화번호 정보 없음") · 🚶 기준점에서 도보 약 N분.
4. 대화 말풍선: 사용자 = 핑크(`#ff8fa3`) 오른쪽, 봇 = 흰색 왼쪽.
5. 입력창 + 📍 버튼.

**지도 그리는 방식 [결정]:** 핀은 실제 좌표 비율대로 찍고, 배경(숲·길·강·블록)은 위 스타일로 꾸며서 그린다. 실제 지도 타일을 쓰지 않는다. 실제 골목을 보여주지 않아도 된다.

### 3.3 지도 접힘 — B안 "요약 바 + 장소 칩" (`result-folded-b.html`)
- 지도 자리에 얇은 흰 바: 미니맵 썸네일 + "**광화문 근처** · 추천 N곳" + "지도 보기 ▾".
- 그 아래 가로로 넘기는 장소 칩: "🍽️ 세종클럽 3분", "🥟 개성만두 궁 12분" … (맛집 칩 주황 테두리, 관광지 칩 분홍 테두리).
- **칩을 누르면 지도를 펼치지 않고 바로 정보 카드가 뜬다.**
- 대화창이 그만큼 넓어진다. 상단 바 문구는 "▴ 지도 펼치기".

### 3.4 화면 상태 흐름
첫 화면(S2a) → 첫 질문 전송 → 추천 결과(지도 펼침) ⇄ 지도 접힘(B안).
새 추천이 나오면 **기존 핀을 지우고 새 핀으로 바꾼다** (누적하지 않음) **[결정]**. 요약 바의 "○○ 근처 · 추천 N곳"과 칩도 새 결과로 바뀐다.
추천이 없는 답변(인사·감사 등)은 지도를 바꾸지 않는다 **[제안]**.

## 5. 백엔드 (FastAPI 하나) [결정]

### 5.1 구성
- Python 3.11, FastAPI. **화면 정적 파일도 FastAPI가 같이 서빙** **[제안]** → 실행할 프로그램이 하나.
- 검색: 이미 켜져 있는 OpenSearch(`localhost:9200`)의 kNN 벡터 검색, 임베딩 `jhgan/ko-sroberta-multitask`(768차원). 기존 `vectorize.py`를 정리해 `scripts/build_index.py`로 재작성하고, 문서에 `contentid`, `type`, `cat3`, 좌표(`geo_point`), 이미지, 보강 전화번호까지 넣는다 **[제안]**.
- 인덱스 이름은 **새 이름 `seoul-tour-v2`** 를 쓴다. 기존 `seoul-tour` 인덱스는 지우거나 덮어쓰지 않는다 **[제안]**. 인덱스 이름은 `.env`로 바꿀 수 있게.
- 답변 생성: 로컬 Ollama(`localhost:11434`), 모델 **`gemma4:e4b`**(이 PC에 설치된 유일한 모델; 기존 코드의 `gemma3:4b`는 없음).
- 대화 기록: 이미 켜져 있는 MySQL(`localhost:3306`, DB `seoul_tour`). 기존 `chat_history` 테이블은 건드리지 않고 **새 테이블 `chat_message`** 를 만든다: `id, session_id, role, message, center_json, places_json, created_at` **[제안]**. 봇 답변마다 기준점과 추천 장소를 함께 저장해서, 새로고침해도 **대화 + 지도 + 핀 + 칩이 모두 복원**된다. 기존 정책 유지: 세션당 최근 100개, 30일 지난 기록 삭제 **[제안]**.
- 세션의 "직전 기준점"과 "직전 추천 장소"는 이 테이블의 마지막 봇 메시지에서 읽는다 (서버 메모리에 따로 두지 않음) **[제안]**.
- 접속 정보는 모두 `.env`에서 읽는다 (OpenSearch 계정, MySQL 계정, Ollama 주소/모델, 관광 API 키).

### 5.2 "근처" 기준점 정하기 [결정 + 제안]
우선순위:
1. 요청에 GPS 좌표가 있으면 → 그 좌표. (사용자가 📍를 누른 경우)
1-1. 질문에 "거기", "그 근처", "그 주변", "거기 근처" 같은 지시어가 있고 질문 속에 다른 장소 이름이 없으면 → **방금 추천한 장소** **[결정]**. 사용자가 정보 카드를 열어 본(핀·칩을 누른) 장소가 있으면 그 장소, 없으면 직전 답변의 첫 번째 추천 장소 **[제안]**. 예: "광화문 근처 맛집" → 개성만두 궁 카드 열람 → "거기 근처 카페 있어?" = 개성만두 궁 근처 카페.
2. 질문에 데이터셋 장소 이름이 있으면(예: "광화문") → 그 장소 좌표.
   - 여러 장소가 걸리면(광화문 / 광화문광장 …) 제목이 정확히 같은 것 → 가장 긴 일치 → 가장 짧은 제목 순으로 하나를 고른다 **[제안]**.
3. 질문에 동네·역 이름이 있으면(예: "성수", "홍대", "강남역", "명동", "인사동", "이태원", "잠실", "여의도") → 인기 지역 이름표(이름 → 좌표, 30곳 안팎 상수)의 좌표. 이름표에 없으면 `addr1`의 동 이름과 맞춰서 그 동 데이터의 평균 좌표 **[제안]**. 첫 화면 칩 "☕ 성수 카페"가 이 규칙으로 동작해야 한다.
4. 질문에 구 이름이 있으면(예: "종로구") → 그 구에 속한 데이터의 평균 좌표 **[제안]**.
5. 없으면 직전 대화에서 쓰인 기준점(세션에 저장).
6. 그래도 없으면 기준점 없이 의미 검색만.

### 5.3 추천 고르기 [제안]
- 질문 의도(맛집/카페/관광지/전체)를 키워드로 판단해 `type` 필터.
- 기준점이 있으면: 기준점 반경 **1.5km** 안에서 벡터 유사도로 상위 3~5곳, 거리순 정렬. 반경 안에 없으면 가장 가까운 곳들을 주고 답변에 "가장 가까운 곳은 2.3km 떨어진 ○○예요"처럼 거리를 밝힌다.
- 거리: 하버사인 직선거리. 도보 시간 = 거리 ÷ 67m/분(약 4km/h), 반올림.
- 인사·감사 같은 일상 대화는 기존 `main.py`처럼 키워드로 감지해 고정 답변(장소 없음).
- LLM에게는 검색된 장소 정보와 최근 대화만 주고, **장소 목록(JSON)은 LLM이 아니라 검색 결과에서 만든다** (지어낸 장소 방지).

## 6. 프론트엔드 [결정: HTML/CSS/JS]
- 프레임워크 없음. `static/index.html`, `static/css/`, `static/js/` **[제안]**.
- 지도는 **SVG로 직접 그린다**: 추천 장소들 + 기준점이 들어가는 범위(bbox)를 잡고, 위경도를 비율로 화면 좌표로 바꿔 핀을 찍는다. 배경 장식(숲·길·블록)은 매번 같은 결과가 나오도록 기준점 좌표를 시드로 배치 **[제안]**. 강은 범위가 한강 근처일 때만 그리면 자연스럽다 **[빌더]**.
- 6대 랜드마크의 좌표는 상수로 두고, bbox 안에 있으면 미니 일러스트를 그린다 **[제안]**.
- 세션 ID는 `localStorage`에 저장, 새로고침하면 `/api/history`로 대화 복원.
- GPS: 📍 누르면 `navigator.geolocation`으로 좌표를 받아 다음 질문에 함께 보냄. 거부/실패 시 말풍선으로 안내. **휴대폰 브라우저는 https 또는 localhost에서만 위치를 준다** → 휴대폰 시연 방법은 §8.
- 시안 HTML의 CSS 색·크기·SVG 함수를 그대로 옮겨 쓴다.
