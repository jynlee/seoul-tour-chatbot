# 추천 코스 설계 (2026-10-28)

> 사용자가 질문 없이 설계안부터 요청했다. 아래 결정은 대부분 **리드 판단**이며, 사용자가 직접 정한 것은 "데이터 먼저 → 그다음 추천 코스" 순서와 예시 질문 두 개뿐이다. 승인 전에 고칠 곳을 표시해 주면 반영한다.

## 1. 왜 만드나

지금 챗봇은 "○○ 근처 맛집 5곳"처럼 **한 종류 장소 목록**만 준다. 사용자가 처음부터 원한 질문 중에는 목록이 아니라 **순서 있는 하루 동선**을 원하는 것이 있다.

- "기념일인데 서울 데이트 추천 코스"
- "쇼핑하고 맛집 갈 건데 추천 코스"

데이터 확장(3,441곳)으로 한 동네 안에서 관광지·음식점·카페를 이어 붙일 만큼 장소가 생겼으니 이제 만들 수 있다.

## 2. 목표 / 비목표 / 실패로 보는 것

**목표**
- "코스" 질문에 **3~4곳을 순서대로**, 걸어서 이어지는 동선으로 준다.
- 질문에 든 종류를 코스에 반영한다: 데이트 / 쇼핑+맛집 / "궁 보고 밥" 같은 직접 조합 / 종류 없이 "코스 짜줘".
- 지도에 **번호 핀과 순서 점선**, 카드에 **앞 장소에서 도보 몇 분**이 보인다.
- 멀티턴: "2번 거기 주차돼?"(기존 순서 지칭 그대로), "다른 코스"(보여 준 곳 빼고 새 코스).

**비목표 (1차에서 안 함)**
- 영업시간·요일을 따진 시간표(상세 정보의 시간이 자유 문장이라 믿을 수 없음). 대신 "가기 전에 영업시간 확인" 한 줄을 붙인다.
- 코스 안 한 곳만 바꾸기("2번만 다른 데로") — 2차 후보.
- 대중교통·차량 이동, 여러 동네를 넘나드는 하루 일정, 1박 2일.
- Neo4j 등 새 저장소. 지금의 카탈로그 + OpenSearch로 그때그때 만든다.

**실패로 보는 것**
- 장소끼리 멀어서 걸을 수 없는 코스(예: 1번 종로, 2번 강남).
- 같은 장소의 세부 시설이 두 칸을 차지(경복궁 → 경복궁 건청궁).
- 데이트 코스에 둘레길·기관 시설처럼 분위기와 먼 곳, 쇼핑 코스에 쇼핑이 없음.
- 지금 잘 되는 단일 추천·멀티턴이 나빠짐.

## 3. 무엇을 코스 질문으로 보나 (리드 판단)

- 코스 말: `코스`, `동선`, `루트`, `일정 짜`, `하루 일정`, `순서대로`. 이 말이 있으면 코스 모드.
- "데이트 추천해줘"처럼 코스 말이 없으면 **지금처럼 단일 추천**(바꾸지 않음).
- 장소 정보 질문·일상 대화 판정이 코스보다 먼저인 지금 순서는 그대로 둔다.

## 4. 코스 구성 (리드 판단)

질문에서 테마를 고르고, 테마마다 **칸(역할) 순서**를 정한다. 각 칸은 기존 Intent(종류·cat3·세부 주제)로 표현한다.

| 테마 | 판정 | 칸 순서 |
|---|---|---|
| 데이트 | `데이트`, `기념일`, `연인`, `여자친구/남자친구` | 볼거리(전시·산책·역사) → 맛집 → 카페 → 야경 |
| 쇼핑+맛집 | `쇼핑`·`시장`·`백화점` 등 + 음식 말 | 쇼핑 → 맛집 → 카페 |
| 직접 조합 | 질문에 든 종류를 **말한 순서대로** ("궁 보고 밥 먹고 카페") | 말한 순서, 최대 4칸 |
| 기본 | 종류 말 없이 "코스 짜줘" | 관광지 → 맛집 → 관광지 → 카페 |

- 야경 칸은 맞는 곳(세부 주제 '야경')이 동선 안에 없으면 **빼고 3곳**으로 끝낸다(억지로 먼 곳을 넣지 않음).
- 축제는 질문에 축제 말이 있을 때만 칸으로 넣는다.

## 5. 동선 만들기 (리드 판단)

1. **시작점**: 기존 기준점 규칙 그대로(장소·지역·구·GPS·이어받기). 기준점이 없으면 첫 칸을 서울 전체에서 관련도로 고르고 그곳이 시작점.
   - 구 기준이면 첫 칸은 구 안에서 고른다(이후 칸은 아래 반경 규칙).
2. **다음 칸**: 직전 칸 장소에서 **800m 안**의 그 칸 후보 중 관련도(+세부 주제 가점)가 가장 높은 곳. 없으면 1.5km까지 넓히고, 그래도 없으면 그 칸을 뺀다(최소 3곳 못 채우면 "이 근처로는 코스를 짜기 어렵다"고 솔직히 말하고 단일 추천처럼 가까운 곳들을 준다).
3. 이미 고른 곳·그 세부 시설(`one_per_group` 규칙)·기준점 장소는 다음 칸에서 뺀다.
4. 전체 걷는 거리가 약 3km를 넘지 않게 한다(넘으면 마지막 칸부터 더 가까운 후보로 바꿈).
5. **카페 칸이 비기 쉽다**: 카페 데이터가 서울 전체 272곳뿐이다(리드가 실데이터로 확인, 아래 표). 카페 칸이 1.5km 안에서 비면 그 칸을 빼고, 답에 "이 근처는 카페 정보가 적어 코스에서 뺐어요"라고 밝힌다. 다른 음식점으로 대신 채우지 않는다.

   | 시작점 | 800m 안 관광·음식·카페·쇼핑 | 1.5km 안 |
   |---|---|---|
   | 경복궁 | 79·31·16·5 | 199·108·31·13 |
   | 명동 | 46·66·4·18 | 186·152·23·34 |
   | 성수 | 13·48·26·2 | 25·87·58·5 |
   | 여의도 | 8·19·**0**·2 | 32·43·**0**·5 |
   | 마곡 | 6·4·3·1 | 11·16·5·2 |

6. 후보는 기존 kNN(`searcher.knn`, `near` 필터)으로 칸마다 한 번씩 가져온다. 임베딩 질의 문장은 원문 질문 + 칸 이름("데이트 코스 카페").

## 6. 응답 계약 (리드 판단, TEAM-STATUS ④에 기록)

기존 `ChatResponse`에 **선택 필드만 추가**해 단일 추천 화면이 그대로 동작하게 한다.

```
ChatResponse.course: bool = False          # true면 places 순서가 코스 순서
PlaceOut.step: str | None = None           # "볼거리"·"점심"·"카페"·"야경" 등 칸 이름
PlaceOut.leg_m: int | None = None          # 앞 장소에서 거리 (첫 곳은 기준점에서, 기준점 없으면 null)
PlaceOut.leg_walk_min: int | None = None
```

- `places`에 순서대로 담으니 "2번 거기"·"마지막 곳" 지칭은 지금 코드 그대로 동작한다.
- 대화 기록은 places_json에 새 필드가 같이 저장되므로 DB 변경 없음. 기록을 불러올 때 `step`이 있으면 코스로 그린다.
- "다른 코스": 코스 직후 `다른`/`또` + 코스 말이면 같은 시작점·테마로, 보여 준 곳을 빼고 다시 만든다.

## 7. 답변 문장

- LLM 프롬프트에 칸 순서·장소·도보 분을 주고 "1번에서 무엇을 하고, 몇 분 걸어 2번으로…" 식의 짧은 흐름을 쓰게 한다. 장소 이름은 대괄호를 뗀 이름으로 넘긴다(알려진 한계 하나를 여기서 같이 줄임).
- LLM이 안 되면 템플릿: `1. 경복궁(볼거리) → 도보 9분 → 2. ○○(점심) → …`.
- 끝에 "영업시간은 가기 전에 한 번 확인해 주세요." 한 줄.

## 8. 화면 (리드 판단, 시안 확인 필요)

- 지도: 핀 안에 **번호(1·2·3·4)**, 핀끼리 **순서대로 점선**. 일러스트 지도 톤 유지.
- 접힘 요약 바: "종로 · 데이트 코스 4곳" (코스가 아니면 지금 그대로).
- 칩: `1 경복궁` `2 ○○식당` …, 카드에 칸 이름 배지와 "🚶 앞 장소에서 약 N분".
- 사용자 화면 취향(헤더 A·배지·Jua 글꼴)에 맞춰 시안을 먼저 보여 주고 고른 뒤 만든다.

## 9. 테스트

- 단위: 코스 말·테마 판정, 칸 순서, 800m→1.5km 넓히기, 칸 빼기, 세부 시설 중복 없음, 총거리 제한, 계약 필드.
- 통합(실데이터 v3): "종로 데이트 코스", "명동 쇼핑하고 맛집 코스", "성수 코스 짜줘", "홍대 근처 코스" → 연속 장소 간 1.5km 이하, 같은 묶음 없음, 쇼핑 테마에 쇼핑 1곳 이상.
- 회귀: 기존 단위 437·통합 51·JS 52·화면 확인 전부 통과.
- 화면: 번호 핀·점선·칩·카드·기록 다시 불러오기.

## 10. 진행 방식

- 브랜치 `feat/course`(worktree `.claude/worktrees/course`). 백엔드 → 프론트(시안 확인 후) → QA → main.
- 데이터 이어 받기(feat/data)와 겹치지 않는다. 남은 개요가 들어와도 코스 로직은 그대로이고 재색인만 하면 된다.

## 11. 빌더에게 맡기는 것

- 코스 말·테마 말 목록의 세부, 칸 이름 문구.
- 800m / 1.5km / 3km 값은 통합 테스트 결과로 조정 가능(바꾸면 TEAM-STATUS에 기록).
- 점선·번호 핀의 정확한 모양(시안에서 사용자 선택).
