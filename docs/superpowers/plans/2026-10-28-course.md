# 추천 코스 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** "데이트 코스"·"쇼핑하고 맛집 코스" 같은 질문에 걸어서 이어지는 3~4곳을 순서대로 추천하고, 지도에 번호 핀·순서 점선으로 보여 준다.

**Architecture:** 새 모듈 `app/course.py`가 질문 → 코스 계획(칸 목록)을 만들고, 칸마다 기존 kNN(`searcher.knn`의 `near` 필터)으로 직전 장소 근처 후보를 골라 이어 붙인다. `ChatService.handle`은 장소 정보·일상 대화 판정 뒤, 일반 추천 전에 코스 분기를 탄다. 응답 계약은 선택 필드만 늘려 기존 화면이 그대로 동작하고, 프론트는 `places[i].step`이 있으면 코스로 그린다.

**Tech Stack:** Python 3 / FastAPI / pydantic, OpenSearch kNN, Ollama LLM, 순수 JS(ES 모듈) + `node --test`, pytest.

**Spec:** `docs/superpowers/specs/2026-10-28-course-design.md`

## Global Constraints

- 브랜치 `feat/course`, worktree `.claude/worktrees/course`. 강제 push 금지, main 병합은 리드만.
- 커밋·PR에 `Co-Authored-By: Claude`나 "Generated with Claude Code" 문구를 넣지 않는다.
- 포트: 8000·8001 리드 전용. 백엔드 8011, QA 8012~8014. 인덱스는 `seoul-tour-v3`(읽기만). `food-materials`·`seoul-tour`·v2는 건드리지 않는다.
- 테스트 대화 세션은 `test-*`로 만들고 끝나면 `chat_message`에서 지운다. 한글 POST는 Python urllib로.
- `static/zz-harness.html`은 커밋하지 않는다.
- 코스 말: `코스`, `동선`, `루트`, `일정 짜`, `하루 일정`, `순서대로`.
- 데이트 말: `데이트`, `기념일`, `연인`, `여자친구`, `남자친구`. 데이트 말이 있고 장소 종류 말이 없으면 코스 말이 없어도 데이트 코스(사용자 결정). 종류 말이 있으면("데이트하기 좋은 카페") 지금처럼 단일 추천.
- 칸 순서: 데이트 = 볼거리 → 맛집 → 카페 → 야경. 쇼핑+맛집 = 쇼핑 → 맛집 → 카페. 직접 조합 = 말한 순서(최대 4칸). 기본 = 관광지 → 맛집 → 관광지 → 카페.
- 거리 값: 다음 칸은 직전 장소 800m 안, 없으면 1,500m, 그래도 없으면 칸을 뺀다. 칸 사이 걷는 거리 합 ≤ 3,000m. 최소 3곳, 못 채우면 코스 실패.
- 답 끝에 항상 `영업시간은 가기 전에 한 번 확인해 주세요.`
- 카페 칸이 비면 다른 음식점으로 채우지 않고 빼며, 답에 `이 근처는 카페 정보가 적어 코스에서 뺐어요.`를 밝힌다. 야경 칸은 조용히 뺀다.

알고리즘(스펙 §5): 칸마다 `embedder.encode(f"{message} {step.label}")`로 `searcher.knn(vector, step.content_types, step.cat3, 100, near=...)`.
- 첫 칸: 기준점이 반경형(gps·place·area·history)이면 `near=(center, 1500)`; 구(`source=="gu"` 또는 history인데 label이 구)이면 near 없이 kNN 후 `p.gu == 구`만; 기준점 없으면 near 없이 서울 전체.
- 다음 칸: `near=(직전 장소, 800)` → 비면 `(직전 장소, 1500)` → 비면 칸 빼기.
- 후보 거르기: 좌표 있음, `exclude_cat3` 아님, `exclude_ids`·이미 고른 곳 아님, 기준점 장소와 그 세부 시설(같은 group_key·1km 안) 아님, 이미 고른 곳과 `one_per_group` 규칙상 같은 묶음 아님, 칸 사이 걷기 합이 3,000m를 넘지 않음, `required_topic`이면 `matches_topic`.
- 후보 순서: 주제 가점(`recommend.py`의 boost와 같은 식: 제목에 질문 주제 말 +2, 주제 분류·패턴 +1) 내림차순, 그 안에서 kNN 순서.
- leg: 첫 칸은 기준점에서(기준점 없거나 구면 None), 다음 칸은 직전 장소에서. `leg_walk_min = walk_min(leg_m)`. `distance_m`·`walk_min`은 None으로 둔다(코스에서는 leg만 씀).
